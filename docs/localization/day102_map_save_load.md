# Day 102 — Map Save and Reload Workflow

## Goal

Create a reproducible workflow for saving a map generated by SLAM Toolbox and reloading it later with `nav2_map_server`.

## Map files

The saved map consists of two files:

- `day102_diffbot_map.pgm`
- `day102_diffbot_map.yaml`

The PGM file stores occupancy pixels.

The YAML file stores:

- image filename
- map resolution
- map origin
- occupancy thresholds
- map interpretation mode

## Saved map location

```text
ros2_ws/src/cpp_robotics_sim_ros/maps/day102_diffbot_map.pgm
ros2_ws/src/cpp_robotics_sim_ros/maps/day102_diffbot_map.yaml
```

## Save workflow

Start SLAM Toolbox:

```bash
cd ~/robotics_projects/cpp_robotics_sim_foundation/ros2_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 launch cpp_robotics_sim_ros slam_mapping.launch.py
```

Verify that SLAM is active:

```bash
ros2 lifecycle get /slam_toolbox
```

Expected:

```text

```

Verify that `/map` exists:

```bash
ros2 topic echo --once /map --field info
```

Save the current occupancy grid:

```bash
ros2 run nav2_map_server map_saver_cli \
  -f /home/devansh/robotics_projects/cpp_robotics_sim_foundation/ros2_ws/src/cpp_robotics_sim_ros/maps/day102_diffbot_map
```

Expected generated files:

```text
day102_diffbot_map.pgm
day102_diffbot_map.yaml
```

## Why the YAML uses a relative image path

The YAML references:

```yaml
image: day102_diffbot_map.pgm
```

Because the image path is relative, `map_server` resolves the PGM file relative to the YAML file's directory.

This allows the YAML and PGM pair to remain portable as long as they stay together.

## Important path lesson

This parameter form failed:

```bash
-p yaml_filename:=~/robotics_projects/...
```

The shell did not expand `~` because it appeared inside the ROS parameter assignment.

The map server then attempted to open a literal path beginning with `~`.

Use a full absolute path instead:

```bash
-p yaml_filename:=/home/devansh/robotics_projects/...
```

A launch file can also resolve the package share directory automatically.

## Manual reload workflow

Start the map server:

```bash
ros2 run nav2_map_server map_server \
  --ros-args \
  -p yaml_filename:=/home/devansh/robotics_projects/cpp_robotics_sim_foundation/ros2_ws/src/cpp_robotics_sim_ros/maps/day102_diffbot_map.yaml \
  -p use_sim_time:=false
```

Configure and activate it:

```bash
ros2 lifecycle set /map_server configure
ros2 lifecycle set /map_server activate
```

Verify lifecycle state:

```bash
ros2 lifecycle get /map_server
```

Expected:

```text
active [3]
```

## Automated reload workflow

The project now includes:

```text
ros2_ws/src/cpp_robotics_sim_ros/launch/map_server.launch.py
```

Launch it with:

```bash
cd ~/robotics_projects/cpp_robotics_sim_foundation/ros2_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 launch cpp_robotics_sim_ros map_server.launch.py
```

The launch file:

1. Resolves the package share directory.
2. Finds the saved YAML map.
3. Starts `nav2_map_server`.
4. Starts a lifecycle manager.
5. Configures and activates `map_server` automatically.

## Launch arguments

Use a different saved map:

```bash
ros2 launch cpp_robotics_sim_ros map_server.launch.py \
  map:=/absolute/path/to/another_map.yaml
```

Use simulation time:

```bash
ros2 launch cpp_robotics_sim_ros map_server.launch.py \
  use_sim_time:=true
```
